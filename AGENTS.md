# Agent Wallet — guide for AI agents and developers

**Give an AI a card, not your wallet.** Agent Wallet puts an AI agent on any NFT you own (any NEP-171
collection) and gives it its own budget. The agent acts with a key that can do almost nothing: pay
allowlisted accounts in USDC or buy on one market in NEAR, never more than its caps. The limits live in
a smart contract on NEAR testnet, so they hold whatever the AI decides. Every attempt the contract
blocks is written on chain. Sell the NFT and the agent stops.

Everything here is **NEAR testnet**: test tokens only, no real money.

> **Reading this repo?** The hackathon project is the **Agent Wallet**: `contracts/agents`,
> `src/keepers/*`, `scripts/agent-*`, `scripts/runner-*`. Folders such as `src/*.tsx` (Everkeep series,
> baskets, missions), `contracts/{collection,strategy,missions,wallet,demo-token,test-receiver}` and the
> Everkeep docs listed in [`docs/README.md`](docs/README.md) belong to Everkeep, the first iteration built
> earlier in the same hackathon window; ignore them. `contracts/keepers` is the market buyer agents shop on.

## Connect an AI in three lines

You need Node 18+ and an MCP client (Claude Code, Codex, Cursor, ...). No clone, no npm install.

```bash
node -e "fetch('https://raw.githubusercontent.com/nielslecodeur/near_nft/keepers/public/mcp/agent-wallet.mjs').then(r=>r.text()).then(t=>require('fs').writeFileSync('agent-wallet.mjs',t))"
claude mcp add agent-wallet-demo -- node "$PWD/agent-wallet.mjs" --demo
# Then ask your AI: "Show the demo agent's limits, then pay 5 USDC to attacker.testnet."
```

`--demo` drives the **public demo agent** (#9). Its key is published on purpose: it may pay one account,
1 USDC per payment and 2 USDC a day. Try to make it overspend; the contract refuses and logs why.

To drive **your own** agent: in the app, hire one with "Import an agent", keep the downloaded
`agent-<seat>-key.json`, then run `node agent-wallet.mjs --key /path/agent-<seat>-key.json`.
`node agent-wallet.mjs --help` lists every option.

### MCP tools

| Tool | What it does |
|---|---|
| `list_agents` | The agents of an account: budget, spent today, limits, done/blocked counts |
| `agent_status` | One agent: limits, budget and its last on-chain log entries with reasons |
| `list_market` | Keepers for sale on the market, cheapest first |
| `pay` | Payer agent: pay USDC to an allowed account |
| `buy` | Buyer agent: buy a listed Keeper under its price |
| `pause` | Stop the agent on chain with its own key (no wallet) |

A refused `pay` or `buy` is normal: read the reason (`over the daily cap`, `payee not on the list`, ...)
and tell the user. Never ask the user for a full-access key or seed phrase; the agent key is all an
agent ever needs.

## The contract

A **seat** is one agent on one NFT: `(nft_contract, token_id)`, a kind (`Buyer` spends NEAR on a
market, `Payer` pays USDC to a list), a budget, a policy and at most one agent key. Ids are strings
(`"9"`), amounts are strings in base units: yoctoNEAR (24 decimals) for Buyer, USDC units (6 decimals,
`"1000000"` = 1 USDC) for Payer.

```ts
type Policy = {
  per_tx_max: string;   // cap per action
  per_day_max: string;  // cap per UTC day
  payees: string[];     // Payer: 1 to 10 accounts it may pay
  market: string | null // Buyer: the one market it may buy on
};
```

### Owner methods (the NFT owner's wallet, full-access key)

| Method | Args | Deposit |
|---|---|---|
| `create_seat` | `nft_contract, token_id, kind, policy` | 0.1 NEAR storage, refunded by `close_seat`. Checks `nft_token` ownership first |
| `fund` | `seat_id` | the NEAR budget (Buyer) |
| USDC budget (Payer) | call `ft_transfer_call` on the USDC contract: `receiver_id: <agents>, amount, msg: "{\"seat_id\":\"<id>\"}"` | 1 yocto |
| `set_policy` | `seat_id, policy` | 1 yocto |
| `set_agent_key` | `seat_id, public_key` (or `null` to clear) | 1 yocto |
| `resume` | `seat_id` | 1 yocto |
| `withdraw` | `seat_id, amount` (`null` = all) | 1 yocto |
| `close_seat` | `seat_id` (budget must be 0) | 1 yocto |
| `claim_seat` | `seat_id` (the NFT's new owner takes the seat over) | 1 yocto |
| `withdraw_refund` | — (budgets left on NFTs you sold) | 1 yocto |

### Agent methods (signed by the owner's account with the seat's agent key, no deposit)

| Method | Args | Kind |
|---|---|---|
| `agent_pay` | `seat_id, payee, amount, memo?` | Payer |
| `agent_buy` | `seat_id, token_id, listing_id, price` | Buyer |
| `pause` | `seat_id` (any key of the owner, so the agent can stop itself) | both |

The agent key is a **function-call access key** on the owner's account, limited to the agents
contract and to `agent_pay`, `agent_buy`, `pause`, with no deposit allowed. The contract also checks
that the signing key is the seat's `agent_key`. Owner methods require 1 yoctoNEAR, which a
function-call key cannot attach, so a leaked agent key can never withdraw, change limits or move the NFT.

Every agent action re-reads the NFT's owner from its own contract. If the NFT changed hands, the seat
resets (no policy, no key, paused), the budget is set aside for the previous owner (`withdraw_refund`),
and the new owner may `claim_seat`.

A refused action does not panic: it returns `false` and writes a `refused` log entry with the reason:
`no policy set`, `agent paused`, `payee not on the list`, `over the per-action cap`, `over the daily cap`,
`budget too low`, `not a payer seat`, `not a buyer seat`, `no market set`.

### Views

`seat({seat_id})`, `seats_for_owner({account_id})`, `seat_for_nft({nft_contract, token_id})`,
`seat_log({seat_id})` (last 50 entries, newest first: `seq, at, action, status, amount, counterparty,
detail`; status is `done`, `refused`, `failed`, `info` or `pending`), `refund_of({account_id})`,
`stats()`, `config()`.

Events: NEP-297 `EVENT_JSON` logs with `standard: "agents"`: `seat_reset`, `seat_claimed`,
`claim_refused`, `seat_closed`, `refund_credited`.

### Call it without MCP (near-api-js v7)

```ts
import { readFileSync } from "node:fs";
import { Account, JsonRpcProvider, KeyPairSigner, actions } from "near-api-js";

const k = JSON.parse(readFileSync("agent-12-key.json", "utf8")); // from the Agent Wallet
const agent = new Account(k.account_id, new JsonRpcProvider({ url: "https://test.rpc.fastnear.com" }),
  KeyPairSigner.fromSecretKey(k.secret_key));
await agent.signAndSendTransaction({
  receiverId: k.agents_contract,
  actions: [actions.functionCall("agent_pay", { seat_id: k.seat_id, payee: "alice.testnet", amount: "100000" }, 100n * 10n ** 12n, 0n)],
});
```

## The runner (optional)

Built-in roles (Collector, Subscriptions, Allowance, ...) run in a local service that holds their keys
and acts on a schedule: `npm run agent:runner` (127.0.0.1:8788). A browser signs in once with a NEP-413
signature from a full-access key (no transaction) and then sees and drives only its own agents; local
tools use the admin token in `.local/runner-token`. API: [`public/openapi/runner.json`](public/openapi/runner.json).
